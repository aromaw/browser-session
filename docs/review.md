# 审查与优化记录 · 2026-09-12

基于 main `19282963872b6d71556878da3bc3cba8824f6c86` 审查。保留独立 user-data-dir、系统浏览器、跨平台原生进程 API 的方案。

| 发现 | 风险 / 影响 | 修改与验证 |
| --- | --- | --- |
| Windows 通过 PID 枚举窗口，Go Wait 可能同时释放进程句柄 | 极端时序下 PID 重用可能关闭错误窗口 | 在 Wait 前捕获并持有独立 Windows 进程句柄，退出状态通过该句柄检查；句柄持有期间原进程对象不能被 PID 复用。增加 Wait 后原身份仍保留、拒绝向退出进程发送关闭的原生回归测试 |
| 看护循环每 250 ms 写 run.json 并 fsync | 稳态会话每秒四次写盘，没有提供额外活性保证 | 改为状态/进程身份变化才写，按 PID 排序消除枚举顺序抖动；写失败不更新 checkpoint，下一次继续尝试。100 次相同快照只写一次的回归测试 |
| list 每个会话单独获取完整进程快照 | 会话越多，定期 GUI 刷新越慢 | Statuses 共用一次延迟读取的 boot identity 和 snapshot，受看护会话仅检查锁/状态；CLI 与 GUI 共享。删除前的两次独立安全检查保留 |
| 持有看护锁时一律显示 running | 浏览器尚在启动也被显示已运行 | 结合 run.json 返回 starting；UI 不对 starting/unknown/unmanaged 状态启用打开和删除 |
| CLI 内独有的 __supervise 入口 | GUI 直接启动后子进程可能错误地再打开管理窗口 | 抽出共用 DispatchSupervisor，在创建任何 WebView 前处理；GUI 不依赖额外 CLI binary |
| GUI 异步操作与不可信元数据 | 重复操作、删除误点、HTML 注入 | 按操作禁用控件，准确名称确认删除，后端校验 URL/名称/路径与进程；动态内容一律 textContent，静态资源白名单 embed，限制 CSP，不导航用户网址到管理 WebView |

新增依赖只在 GUI 中使用 Wails；CLI 的二进制仍不链接 WebView。Go 模块升级到最低 1.25，并由 Wails 带入新的 x/sys 版本，需要三平台回归测试。

## 边界与未扩大承诺的部分

- Windows 没有窗口、用户取消退出确认、浏览器 wrapper 自行脱离进程树时，仍优先保留数据并提示手工退出，不增加强杀兜底。
- 单文件 JSON 使用 fsync + 原子替换；未加入数据库。文件系统损坏、磁盘耗尽和断电一致性仍受平台与文件系统约束；删除数据后元数据写入失败可能留下待清理的记录，不能视作事务数据库。
- 清理仍会逐个检查临时会话。活动会话只保留，真正删除前仍持有锁并再次扫描；没有为性能弱化检查。
- 不新增云端服务、自动更新器、Profile 导出或任何账号数据上传。源码/构建包留在原私有仓库。
- 没有新的浏览器登录、权限弹窗人工实机验收；真实 Chrome Storage 自动测试及 GUI/系统 WebView 测试记录分开列在 validation.md，不将编译或 mock 测试声称为全部验收通过。
